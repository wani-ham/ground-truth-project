# Ground Truth

Tools for spotting and countering foreign disinformation during election periods. This repository is an early-stage demo.

| Tool | Status | Purpose |
| --- | --- | --- |
| **ARGUS** | Demo available | Visualizes how a disinformation narrative spreads and shows how its pattern can trigger an early warning |
| **GAIA** | Planned | Not built yet |

**[Open the ARGUS demo](https://wani-ham.github.io/ground-truth-project/argus/)**

> **Simulated data.** Every country, outlet, account, politician, and claim in the demo is fictional. ARGUS does not collect live data, and it does not send alerts.

## ARGUS

Foreign disinformation often follows a repeatable path:

```
State media → Proxy sites → National outlets → Social media → Politicians and broadcasters
```

By the time a politician or major broadcaster repeats a claim, it is already in mainstream debate. ARGUS makes the path visible and demonstrates how the earlier stages could warn election authorities, governments, political parties, and civil society in time to respond.

### What the demo shows

The demo replays one false claim, that postal ballots are being swapped at sorting centres, as it spreads through 59 entities in four invented EU member states over 14 simulated days.

- **Network graph:** animated spread, with nodes grouped by stage and country and sized by influence.
- **Timeline:** play, pause, scrub, and change speed.
- **Early-warning panel:** live signal scores and the current alert stage.
- **Source tracing:** select an entity to see how the claim reached it.
- **Alert briefing:** a draft alert with evidence and recommended actions. An analyst must confirm the review before a simulated send.
- **Table view:** a text version of the network.

### How the warning works

ARGUS combines four signals, each scored from 0 to 100:

| Signal | Weight | What it measures | Scores 100 at |
| --- | ---: | --- | --- |
| Coordination | 30% | Matching posts from an account cluster within 12 hours | 12 posts |
| Cross-border jump | 25% | Member states reached within 72 hours | All 4 states |
| Velocity | 25% | Pickups in the last 24 hours against the prior daily baseline | 4× baseline |
| Source laundering | 20% | Proxy sites carrying the claim | All 6 sites |

Velocity scores 0 until there are at least 5 pickups in 24 hours. Each signal holds its peak, so an alert never clears by itself.

| Stage | Criteria |
| --- | --- |
| Monitor | Score below 35 |
| Elevated | Score from 35 to 74 |
| Warning | Score of 75 or higher, with no politician or broadcaster pickup |
| Critical | Score of 75 or higher, with at least one politician or broadcaster pickup |

The other three signals can reach only 70 combined, so Warning always requires some evidence of coordination.

### Limitations

- The spread is generated by a seeded simulation, so every replay is identical.
- The weights and thresholds are illustrative. They have not been calibrated or tested against real campaigns.
- The lead time shown in the demo comes from the simulation and is not a measure of real-world accuracy.
- Once the other signals are at their maximum, two or three matching posts can trigger Warning. A production system would need stricter rules to limit false alarms.
- Repeating a claim does not by itself show intent to deceive. Any real deployment would need human review before naming or acting on an entity.

## Run locally

Requires Node.js 22 (22.12 or newer), 24, or 26.

```bash
cd apps/argus
npm install
npm run dev
```

Then open the local URL that Vite prints.

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the development server |
| `npm test` | Run the logic tests |
| `npm run build` | Type-check and build for production |
| `npm run preview` | Serve the production build |

## Project structure

```
apps/argus/
  src/data/scenario.ts        Fictional entities and spread simulation
  src/engine/detection.ts     Signal scoring and alert stages
  src/engine/playback.ts      Timeline and tracing helpers
  src/components/             Graph, timeline, panels, and alert briefing
.github/workflows/            GitHub Pages deployment
```

Built with React, TypeScript, Vite, and d3-force. Every push to `main` runs the tests and deploys the site to GitHub Pages.
